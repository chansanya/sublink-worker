# 规则系统与分流架构

分流的核心在于**顺序匹配**：客户端从第一条规则逐行扫描，只要匹配即执行出站动作。如果将范围极广的大分类（如包含所有国内网站的规则）排在特定的应用分类之前，该特定分类的流量就会提前被大分类截走。

> 1. `REJECT`（拒绝出站）仅存在于「🛑 广告拦截」及用户自定义的高级策略组中。所有常规应用分类、主控组（🚀 节点选择）以及最后的兜底组（🐟 漏网之鱼）都已剔除 REJECT，杜绝误触断网。

## 包含冲突与拓扑推荐排序

### 1. 冲突预警算法
前端启动时会异步请求 `/api/geosite/:name`，从 MetaCubeX 规则仓库展开并统计全量分类名单。当满足以下条件时，前端会精准提示冲突：
- 细分规则 A 排在 粗分规则 B 之后；
- 规则 A 中有大量域名（如超过 30% 或绝对数量 ≥ 20 个）已经被规则 B 覆盖。

### 2. 一键推荐排序原理
点击「推荐排序」按钮，算法执行以下排序逻辑：
1. **🛑 广告拦截** 永远置于最首位（优先净化网络）；
2. **纯 IP 分类**（如私有网段）排在其后；
3. 其余分类根据 MetaCubeX 域名树的包含关系执行**拓扑排序**；
4. 相同层级下按域名总数升序排列，使大合集（如 `Non-China`）自然落入末尾。
排序结果在数学上保证**零规则截胡**。
