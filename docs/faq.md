# 常见问题 (FAQ)

---

### Q1: 客户端导入订阅时提示网络错误或解析失败？

请按以下顺序排查：
1. **浏览器直接访问**：将生成的订阅 URL 粘贴到浏览器地址栏访问，观察 Worker 返回的具体内容：
   - 若返回 `Missing config parameter`，说明输入的节点文本或订阅源为空；
   - 若返回 `Short URL not found`，说明请求的短链路径在 KV 数据库中不存在；
2. **检查 KV 绑定**：如果是手动通过 `wrangler deploy` 发布的，请确认 `wrangler.jsonc` 中的 `kv_namespaces` id 是否已替换为 `npx wrangler kv namespace create SUBLINK_KV` 生成的真实命名空间 id；
3. **上游机场防火墙**：部分机场会对 Cloudflare Workers 的边缘出口 IP 进行限流或封禁，导致 Worker 抓取订阅超时，此时可直接在工作台粘贴机场节点的明文分享链接或 base64 内容。

### Q2: 为什么苹果 (Apple) 和微软 (Microsoft) 默认直连？

在长期网络体验中，苹果与微软的 CDN 节点在全球拥有极高覆盖度。如果将这两类服务全部导向海外节点，会导致：
- App Store、TestFlight 下载速度骤降或频繁报错；
- Windows Update 与 Office 365 登录触发海外异地风控；
- iCloud 备份占用宝贵的节点流量。

因此，Sublink Worker 将这两类策略组的首项设为 `DIRECT`。若某些特定微软服务需要走代理，只需在客户端策略组中手动切回 `🚀 节点选择` 即可。

### Q3: 修改节点或规则后，需要重新给客户端配置新短链吗？

**完全不需要**。
在工作台第 04 块的「短链」输入框中，输入之前用过的相同短链代号（例如 `my-vpn`），再次点击「生成短链」。系统会自动将全新的配置参数覆盖写入该代号的 KV 记录。客户端在下次定时更新订阅时，无需更改任何链接即可拉取最新配置。

---

### Q4: 为什么移除了原项目的外部底板配置 (POST /config)？

原项目早期支持上传自定义 Clash 或 sing-box 模板底板，但该设计存在明显缺陷：
1. 客户端协议与内核版本迭代极快，用户上传的旧底板经常在新版 Clash Verge 或 sing-box 客户端中崩毁；
2. 跨格式无法共享规则（上传了 Clash 模板无法自动生成 sing-box）；
3. 产生大量无主 KV 存储垃圾，甚至存在注入恶意入站规则的安全隐患。

重构后的架构将内核最优配置内置固化，所有分流需求统一由「18 类可视化分类」与「双层自定义规则」动态生成，兼顾稳定性与灵活性。
