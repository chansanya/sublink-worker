Sublink Worker

下一代轻量化订阅管理中心

一个 Worker 承载所有订阅。将节点链接与机场订阅转换为标准的 Clash、sing-box、Xray 配置；
内置 18 大规则分类、包含冲突拓扑推荐排序、快捷直连/拦截规则、实时抽屉预览与持久化短链。

快速开始 打开转换工作台 GitHub 仓库

多协议聚合转换

支持 ss、vmess、vless、trojan、hysteria2、tuic 与 http(s) 订阅混填，多行聚合去重，统一输出各大客户端标准格式。

拓扑推荐与冲突检测

在线拉取真实域名名单，统计各分类规模；计算分类包含度并预警被截走风险，支持一键拓扑推荐排序，保障分流准确性。

双层自定义分流

快捷模式一行直连/拒绝域名或 IP 段，粘贴自动解析；高级模式支持自定义策略组与 Geo-Site/Geo-IP，默认置顶优先匹配。

零运维边缘部署

基于 Cloudflare Workers ES Module 开发，无需自建服务器与后端维护；Workers KV 驱动自定义短链，毫秒级响应。

01 / DEPLOYMENT

快速开始

Sublink Worker 专为个人自托管设计，零外部依赖，可以通过以下三种方式部署与运行：

方式一：Cloudflare Workers 一键部署（推荐）

如果你不想在本地配置 Node.js 开发环境，可以使用 Cloudflare 官方的 Deploy 流程：

1

点击一键部署按钮

点击仓库 README 中的 Deploy to Cloudflare 按钮，Cloudflare 会将项目 Fork 到你的 GitHub / GitLab 账户。

2

自动绑定 KV 命名空间

Cloudflare 会自动创建一个专属的 SUBLINK_KV 命名空间并注入 Worker。部署完成后，访问你的 *.workers.dev 域名即可直接使用。

3

后续更新与协同

当你向自己的 GitHub 仓库推送更新时，Cloudflare 会自动重新构建并分发到全球边缘节点。

方式二：Wrangler CLI 手动部署

如果你熟悉命令行，可以通过 Wrangler 直接将项目发布到你的 Cloudflare 账户：

bash 
# 1. 克隆仓库并安装依赖
git clone https://github.com/chansanya/sublink-worker.git
cd sublink-worker
npm install

# 2. 登录 Cloudflare 账户
npx wrangler login

# 3. 创建用于持久化短链的 KV 命名空间（记下控制台输出的 id）
npx wrangler kv namespace create SUBLINK_KV

# 4. 将生成的 id 填入 wrangler.jsonc 中的 kv_namespaces 数组
# 5. 执行部署
npm run deploy
Wrangler 配置文件说明 wrangler.jsonc 默认的 KV id 是全零占位符，用来配合一键部署按钮。本地手动发布前必须先替换为自己创建的真实 KV namespace id。

方式三：本地开发与运行

在本地调试转换算法或前端 UI，无需 Cloudflare 真实账号：

bash 
npm install
npm run dev

启动后访问 http://localhost:8787。本地环境会自动在 .wrangler/state 模拟 KV 存储，短链保存与跳转均可离线完整测试。

02 / RULE ARCHITECTURE

规则分类与分流体系

分流的核心在于顺序匹配：规则列表从上往下扫描，第一条命中即决定出站流量。如果把大范围规则（如全量国内服务）排在细分规则（如国内特定流媒体）之前，细分规则就会被“截胡”失效。

18 大统一规则分类

本项目定义了统一的规则字典 UNIFIED_RULES，所有输出客户端（Clash 与 sing-box）共享同一套分类标准：

预设与推荐排序

三档规则预设

精简 (Minimal)：仅保留国内服务、私有网络与非中国，轻巧极简。
均衡 (Balanced)：在精简基础上加入广告拦截、AI 服务、YouTube、GitHub、Telegram、苹果、微软等主流需求。
全面 (Comprehensive)：启用全部 18 类规则，细分到各类社交、流媒体与学术网络。

自由拖拽与推荐排序

在前端工作台可自由拖动卡片调整优先级顺序。点击「推荐排序」，系统会自动将广告拦截置顶、纯 IP 规则排在次位，并根据 MetaCubeX 域名树拓扑计算包含关系：小分类在前、大合集在后，从算法层面实现 0 冲突。

03 / CUSTOMIZATION

自定义规则系统

为满足个性化的例外分流需求，Sublink Worker 提供了独特的双层自定义规则机制：

1. 快捷规则 (Quick Rules)

针对最常见的直连或拦截需求，无需理解复杂的出站策略组，一行完成：

  • 动作选择：直连 (DIRECT) 或 拒绝 (REJECT)
  • 匹配类型：域名 (DOMAIN)、域名后缀 (DOMAIN-SUFFIX)、IP段 (IP-CIDR)
  • 智能解析：支持多个值用逗号、空格或回车分隔；直接粘贴完整 URL 会自动抽取纯域名；输入单 IP 会自动补齐 /32 CIDR 掩码。

2. 高级规则 (Advanced Rules)

在折叠的「高级规则」面板中，你可以创建更加灵活的分流策略：

  • 自定义策略组：出站填入新名称（如 🎮 游戏专线），Builder 会自动在客户端配置中新建该策略组并绑定对应节点。若出站填入 DIRECT 或 REJECT，则直接导向内核内置出站。
  • Geo-Site & Geo-IP：支持调用 Geo 数据库分类名称（前端输入时会自动在线校验名称合法性，填错实时标红）。
  • 关键词与协议：支持 DOMAIN-KEYWORD 关键词匹配及 PROTOCOL 协议分流。
默认置顶 (Pin) 机制 自定义规则默认开启「置顶」。在生成的最终配置中，自定义快捷规则与高级规则排在所有 18 个分类规则之前，优先被内核评估，确保你的例外名单绝对生效。
04 / PREVIEW & SHORT URLS

实时预览与短链服务

侧边抽屉实时预览

工作台右侧提供了一个响应式配置预览抽屉：

  • 多内核格式切换：支持一键切换查看 Clash YAML、sing-box JSON 与 Xray 聚合列表。
  • 防抖请求与改动高亮：在左侧修改节点、勾选分类或添加自定义规则时，预览会在后台防抖请求真实接口，并在右侧高亮显示变动的行。
  • 段落快速跳转：顶部 Chips 支持快速定位到 proxies、proxy-groups、rules、dns 等主要配置块。
  • 收起与展开：抽屉收起时不发起不必要的网络请求；在窄屏或移动端自动转为右侧滑出抽屉。

短链与持久化托管

生成完整的订阅 URL 往往包含复杂的参数字符串，不便于在移动设备输入。Sublink Worker 提供了基于 KV 的短链生成能力：

http 
# Clash 专属短链（自动跳转到 /clash 并在末尾拼接保存的 query 参数）
https://your-domain.workers.dev/c/my-node

# sing-box 专属短链（自动跳转到 /singbox）
https://your-domain.workers.dev/b/my-node

# Xray 专属短链（自动跳转到 /xray）
https://your-domain.workers.dev/x/my-node

短链覆盖更新：如果你修改了节点或规则，并在短链框输入相同的自定义路径，原短链配置会被覆盖更新，客户端无需重新导入地址！

05 / API REFERENCE

API 参考

Sublink Worker 提供纯净的 RESTful HTTP 接口，可供第三方应用、自动化脚本或各类客户端直接调用：

1. 订阅配置输出端点

路径 输出格式 主要查询参数
GET /clash text/yaml; charset=utf-8 (Clash mihomo) config, selectedRules, customRules, pin
GET /singbox application/json; charset=utf-8 (sing-box 1.8+) config, selectedRules, customRules, pin
GET /xray application/json; charset=utf-8 (base64 聚合节点) config

参数规范

  • config（必须）：换行分隔的节点链接（ss:// 等）或 http(s):// 机场订阅地址。
  • selectedRules：预设名称（minimal / balanced / comprehensive），或者 JSON 编码的规则名数组（如 ["AI Services", "Location:CN"]）。
  • customRules：JSON 编码的自定义规则对象数组。
  • pin：布尔字符串 true 或 false，控制自定义规则是否排在最前。

2. 短链生成与跳转

端点 方法 说明
/shorten-v2?url=...&shortCode=... GET 将 URL 的查询参数提取并存储到 KV 中，返回对应的短码。
/c/:code GET 重定向 (302) 到带存储参数的 /clash。
/b/:code GET 重定向 (302) 到带存储参数的 /singbox。
/x/:code GET 重定向 (302) 到带存储参数的 /xray。

3. 内部数据辅助端点

  • GET /api/rules：返回全部规则分类列表与预设定义，供前端渲染卡片。
  • GET /api/geosite/:name：代理 MetaCubeX 已展开 include 的纯文本域名名单，边缘缓存 1 天，用于前端实时计算域名数与两两覆盖包含度。

中间表示机制 (IR)

Sublink Worker 内部以 sing-box outbound 格式 作为中间数据表示：

  • 各类协议解析器（src/ProxyParsers.js）统一将各协议 URL 转换为标准 sing-box outbound 对象。
  • 输出 Clash 格式时，由 src/ClashConfigBuilder.js 的 convertToClashProxy 进行一次无损桥接转换。
  • 策略组名称两端严格对齐：固定生成 🚀 节点选择、⚡ 自动选择、🐟 漏网之鱼（兜底 MATCH）；sing-box 额外包含 GLOBAL。
07 / FAQ

常见问题 (FAQ)

1. 客户端更新订阅提示网络错误或解析失败？

请首先在浏览器中直接打开生成的订阅链接（或短链）：

  1. 如果浏览器返回 Missing config parameter，说明输入的节点信息或订阅源为空。
  2. 如果返回 Short URL not found，说明短链码未在 KV 存储中生效，请检查 wrangler.jsonc 的 KV id 是否正确配置。
  3. 若节点提供商的机场订阅域名被墙或开启了防刷防火墙，Cloudflare Worker 在拉取时可能会超时，可尝试直接粘贴 base64 节点或节点链接本身。
2. 为什么部分分类默认是 DIRECT，而不能全部走代理？

在日常网络环境中，国内服务、私有局域网、苹果服务与微软服务如果强制走代理，极易导致银行 App 风控、本地 NAS 无法访问或应用商店连接迟钝。本项目将这四类策略组的首项设为 DIRECT（开箱即直连），但在策略组里依然保留了节点选项，你随时可以在客户端手动切回代理出站。

3. 如何让多个设备或客户端共用同一个订阅并随时修改？

建议使用工作台第 04 块的「短链」功能：在输入框中填入你喜欢的固定名字（如 my-profile），点击生成短链。将生成的 /c/my-profile 填入 Clash、/b/my-profile 填入 sing-box。以后无论你更换节点还是调整分流规则，只要再次用相同的 my-profile 名字生成短链，KV 会直接覆盖更新，所有设备的订阅地址永不需要重新配置！

4. 为什么移除了原项目的外部底板配置 (POST /config)？

原项目的自定义底板功能允许通过 configId 上传自定义的 Clash/sing-box YAML/JSON 模板，但存在严重的跨客户端兼容性隐患、KV 垃圾冗余和安全风险。重构后，本项目将内核配置（DNS、端口、入站、嗅探等）统一内置调优，并通过可视化的 18 大分类和双层自定义规则取代了原先手工编写脆弱模板的方式，更加安全稳定。
